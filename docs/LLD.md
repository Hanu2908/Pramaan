# Low-Level Design (LLD)

## 1. Database Schema (Supabase PostgreSQL)

The database relies heavily on standard relational modeling and `pgvector` for semantic search.

### `sources` Table
Maintains a list of all ingested data sources and their predefined authority levels.
- `id` (UUID, PK)
- `name` (String, e.g., "PIB", "Alt News", "Factly")
- `type` (Enum: `GOV`, `INDEPENDENT`, `AGGREGATOR`)
- `authority_level` (Integer, 1-10)
- `base_url` (String)

### `topics` Table
Predefined topics for filtering the Proactive Timeline.
- `id` (UUID, PK)
- `name` (String, e.g., "Protests", "Elections", "Geopolitics")

### `evidence_items` Table
The core table containing ingested facts and news.
- `id` (UUID, PK)
- `source_id` (UUID, FK -> `sources.id`)
- `topic_id` (UUID, FK -> `topics.id`)
- `raw_content` (Text)
- `normalized_content` (Text)
- `embedding` (vector(768)) — Generated by `gemini-embedding-001` (outputDimensionality: 768)
- `published_at` (Timestamp)
- `source_url` (String)
- `is_direct_record` (Boolean) - `true` if Lane 1, `false` if Lane 2

### `claim_checks` Table
Stores user queries and the synthesized results for the Reactive Checker.
- `id` (UUID, PK)
- `user_input` (Text)
- `media_url` (String, Optional)
- `synthetic_score` (Float) - From Reality Defender
- `extracted_entities` (JSONB)
- `confidence_tier` (Enum: `CONFIRMED`, `REFUTED`, `DEVELOPING`, `UNVERIFIED`, `NO_RECORD`)
- `synthesized_verdict` (Text)
- `created_at` (Timestamp)

### `evidence_matches` Table (Join Table)
Maps which `evidence_items` were used to reach a verdict for a specific `claim_check`.
- `claim_check_id` (UUID, FK)
- `evidence_item_id` (UUID, FK)
- `similarity_score` (Float)

## 2. Supabase Edge Functions

### `ingest-news`
- **Trigger**: pg_cron every 4 hours (all sources); every 24h for ACLED.
- **Payload**: `{ source: 'all' | 'pib' | 'pib_telegram' | 'altnews' | 'factly' | 'newsdata' | 'acled' }`
- **Logic**: 
  1. Pulls data from PIB RSS, PIB Telegram (`@PIB_FactCheck`), Alt News RSS, Factly RSS, NewsData.io API, and ACLED API.
  2. Idempotent upsert by `source_url` — never duplicates.
  3. Routes to Lane 1 (PIB, ACLED) or Lane 2 (others) via `is_direct_record`.
  4. Calls `gemini-embedding-001` (768 dims) to generate embedding.

### `check-claim`
- **Trigger**: HTTP POST from Frontend / client library (`supabase.functions.invoke('check-claim', ...)`).
- **Payload**: `{ text?: string, media_url?: string, input_type?: 'text' | 'image' | 'audio' }`
- **Logic**: Executes the 7-Stage Engine.
  1. Calls **Groq Vision** (`llama-4-scout-17b-16e-instruct`) for OCR or **Groq Whisper** (`whisper-large-v3-turbo`) for audio transcription if media is present.
  2. Calls **Reality Defender** for `synthetic_score` (if media provided).
  3. Calls **Groq LLM** (`llama-3.3-70b-versatile`) for structured entity JSON (`location`, `date_range`, `actors`, `keywords`, `topic_slug`).
  4. Queries Supabase using entities (Structured SQL Filter).
  5. Generates embedding via `gemini-embedding-001` (768-dim) and runs `pgvector` similarity search (`match_evidence` RPC).
  6. Calculates Confidence Tier (`CONFIRMED`, `REFUTED`, `DEVELOPING`, `UNVERIFIED`, `NO_RECORD`) with explicit refutation keyword checks.
  7. Fallback to **Gemini 2.0 Flash** web grounding if no local DB matches exist.
  8. Synthesizes final response via Groq `llama-3.3-70b-versatile`, strictly constrained to retrieved evidence.
- **Response**: `{ id: string, tier: string, score: number, verdict: string, sources: [], synthetic_score: number | null, used_web_grounding: boolean }`

### `fact-check-lookup`
- Logic: Parses individual article JSON-LD for enhanced metadata.

### `auth-manager`
- Logic: Manages user authentication and role-based access.

## 3. Factly Web Scraping Logic

Factly.in is ingested via its **official RSS feed** at `https://factly.in/category/fact-check/feed/` — no scraping required. The `ingest-news` Edge Function handles this alongside other RSS sources. For enhanced metadata (ClaimReview verdict), the `fact-check-lookup` Edge Function can parse individual article JSON-LD.
- **Target**: Fact-check articles and public data visualizers.
- **Extraction**:
  - `Title` -> `raw_content`
  - `Verdict` (True, False, Misleading) -> metadata
  - `Date`, `Author` -> metadata
- **Rate Limiting**: The scraper will run respectfully (e.g., once every 6 hours) to avoid overloading the target server and will parse the HTML to extract the core text, ignoring ads and boilerplate.
