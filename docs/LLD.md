# Low-Level Design (LLD)

## 1. Database Schema (Supabase PostgreSQL)

The database relies heavily on standard relational modeling and `pgvector` for semantic search.

### `sources` Table
Maintains a list of all ingested data sources and their predefined authority levels.
- `id` (UUID, PK)
- `name` (String, e.g., "PIB", "Alt News", "Factly")
- `type` (Enum: `GOV`, `INDEPENDENT`, `AGGREGATOR`)
- `authority_level` (Integer, 1-10)
- `base_url` (String)

### `topics` Table
Predefined topics for filtering the Proactive Timeline.
- `id` (UUID, PK)
- `name` (String, e.g., "Protests", "Elections", "Geopolitics")

### `evidence_items` Table
The core table containing ingested facts and news.
- `id` (UUID, PK)
- `source_id` (UUID, FK -> `sources.id`)
- `topic_id` (UUID, FK -> `topics.id`)
- `raw_content` (Text)
- `normalized_content` (Text)
- `embedding` (vector(768)) - Generated by Gemini
- `published_at` (Timestamp)
- `source_url` (String)
- `is_direct_record` (Boolean) - `true` if Lane 1, `false` if Lane 2

### `claim_checks` Table
Stores user queries and the synthesized results for the Reactive Checker.
- `id` (UUID, PK)
- `user_input` (Text)
- `media_url` (String, Optional)
- `synthetic_score` (Float) - From Reality Defender
- `extracted_entities` (JSONB)
- `confidence_tier` (Enum: `CONFIRMED`, `DEVELOPING`, `UNVERIFIED`, `NO_RECORD`)
- `synthesized_verdict` (Text)
- `created_at` (Timestamp)

### `evidence_matches` Table (Join Table)
Maps which `evidence_items` were used to reach a verdict for a specific `claim_check`.
- `claim_check_id` (UUID, FK)
- `evidence_item_id` (UUID, FK)
- `similarity_score` (Float)

## 2. Supabase Edge Functions

### `ingest-news`
- **Trigger**: Scheduled (cron) or Webhook.
- **Logic**: 
  1. Pulls data from NewsData.io, PIB, Alt News, ACLED, and Factly.
  2. Normalizes text.
  3. Calls Gemini API to generate `embedding`.
  4. Inserts into `evidence_items`.

### `check-claim`
- **Trigger**: HTTP POST from Frontend.
- **Payload**: `{ text?: string, media_url?: string }`
- **Logic**: Executes the 7-Stage Engine.
  1. Calls Groq Whisper/Vision if media is present.
  2. Calls Reality Defender for `synthetic_score`.
  3. Calls Groq LLM for entity JSON.
  4. Queries Supabase using entities (Structured Filter).
  5. If required, generates embedding via Gemini and runs `pgvector` similarity search.
  6. Calculates Confidence Tier.
  7. Synthesizes final response via Groq.
- **Response**: `{ tier: string, verdict: string, sources: [] }`

## 3. Factly Web Scraping Logic

The ingestion engine will include a dedicated Python/Node script to periodically scrape Factly.in.
- **Target**: Fact-check articles and public data visualizers.
- **Extraction**:
  - `Title` -> `raw_content`
  - `Verdict` (True, False, Misleading) -> metadata
  - `Date`, `Author` -> metadata
- **Rate Limiting**: The scraper will run respectfully (e.g., once every 6 hours) to avoid overloading the target server and will parse the HTML to extract the core text, ignoring ads and boilerplate.
